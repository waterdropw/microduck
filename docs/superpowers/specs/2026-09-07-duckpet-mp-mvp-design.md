# DuckPet 微信小程序 MVP 产品规范

状态：待评审 · 日期：2026-09-07 · 依据：microduck 全栈分析（Impl_Analysis.md 一至五篇）
与 duck-sim Docker 实测（50.0 Hz、全技能可用）

## 1. 产品定位

**独立的虚拟宠物微信小程序**——不预设用户拥有实体 Microduck。核心差异化：虚拟角色的
运动由**真实的强化学习策略**驱动（与实体机器人完全相同的 ONNX 大脑、50 Hz 控制环、
安全层），而非预录动画。"云上跑的就是真机器人的完整软件"是诚实的卖点。

**MVP 的唯一使命**：验证"真 RL 大脑驱动的虚拟宠物"这一差异化体验能否留住用户。

## 2. 已定决策（brainstorming 结论，勿推翻）

| 决策点 | 结论 | 理由 |
|---|---|---|
| 定位 | 独立虚拟宠物游戏，大众向 | 不与实体产品深度绑定，后可导流 |
| 画面传输 | **客户端渲染**（状态同步） | 带宽 ~200B/tick vs 2Mbps 视频流；延迟最小；相机自由；角色=客户端资产包 |
| 社交范围 | v1 单人单鸭 | 服务器模型最简，先做扎实单鸭体验 |
| 角色差异深度 | **皮肤 + 声音人格**，共享物理骨架与大脑 | 皮骨分离：零重训成本，新角色=美术资产包 |
| 商业模式 | 免费 + 皮肤内购（安卓）；iOS 用任务/分享解锁 | 微信平台 iOS 虚拟支付限制 |
| 服务器架构 | **方案一：复用真 daemon 栈，逐会话容器** | 今天已验证可跑；新代码最少；状态桥是唯一协议边界，后端可无痛替换 |

## 3. MVP 范围

### 3.1 做

- 核心循环：打开 → 鸭子在世界中 → 虚拟摇杆驾驶 → 技能按钮（坐/站、前滚翻、
  捡东西）→ 触摸摸头（触发叫声）→ 退出
- 鸭子身份持久化：名字、声音人格种子、皮肤、位置/姿态（重进无缝续上）
- 微信登录（openid）
- 角色系统：1 个版权干净的免费初始角色 + 2–3 个付费皮肤（验证内购链路）
- 单场景：简化房间（MVP 不需要公寓的六房间）

### 3.2 不做（v1 明确排除）

好友/多人/公共广场、麦克风 pet-detect（v2）、等级/任务/成就系统、合唱、
拍照分享、运营后台（用最小查询脚本替代）。

## 4. 系统架构

```
微信小程序（threejs-miniprogram WebGL 渲染 · 虚拟摇杆 · 技能轮盘 · 摸头手势）
   │  WebSocket（JSON）：状态下行 ~30Hz · 意图上行
   ▼
会话网关（新组件，Rust 优先）
   ├─ 微信登录鉴权、会话生命周期（冷启动、心跳、闲置回收）
   ├─ 状态桥：robotd unix socket (robot.state) ↔ WebSocket 关节流【唯一协议边界】
   ├─ 意图翻译：摇杆 → robot.move（twist）；按钮 → robot.do（skill）
   └─ 容器编排：每用户一个仿真单元的创建/回收
   ▼  每用户一个（Docker 容器）
仿真单元（复用 duck-sim 已验证形态）
   ├─ duck-body（MuJoCo 物理躯体，TCP 7801）
   ├─ robotd --sim（50 Hz 真控制环 + ONNX 策略 + 安全层）
   └─ 官方策略集（alpha_walking / alpha_stand / alpha_sitstand /
      alpha_ground_pick / roulade）
用户服务（微信云开发：零运维、与小程序生态原生集成）
   └─ openid、鸭子档案（名字/种子/皮肤/位置）、皮肤归属、支付记录
资产：声音 wav 建号时按种子预合成（sounds crate 服务端）存 CDN；
     角色 glTF 包 + 骨骼映射表存 CDN
```

## 5. 关键数据流

### 5.1 状态下行（30 Hz）

状态桥订阅 `robot.state` → 15 关节角 + 躯干位姿 → 压缩 JSON（~200B/tick）→
小程序蒙皮动画。相机完全客户端控制。关节顺序固定为契约（与 obs.rs 的关节布局
一致），版本化防漂移。

### 5.2 意图上行

- 摇杆：touch 坐标 → 客户端 EMA 平滑 → twist [前进, 左移, 转向] → `robot.move`
- 技能按钮：`robot do <skill>`（sit 切换、roulade、ground-pick）
- 摸头：点按/滑动识别 → 客户端直接播放叫声（MVP 不经服务器；声音资产已本地化）
- 意图超时自停依赖 daemon 现成的 deadman 语义

### 5.3 会话生命周期

```
进入小程序 → 网关校验 → 冷启动容器（2–5s，加载页=孵化动画）
→ 恢复鸭子状态（位置从库续）→ 游玩 → 闲置 10min 自动回收
容器回收前：位置/姿态写库
```

## 6. 角色与资产系统

- **骨架单一**：所有角色共用鸭子的 14 关节物理骨架（服务器侧永远是鸭子）；
  客户端角色是"套在骨架上的皮"
- **角色包** = glTF 模型（骨骼命名/层级对齐鸭子关节契约）+ 材质 + 待机小动画 +
  声音种子预设 + 角色元数据（名称/描述/价格）
- **⚠️ 许可证红线**：仓库中的鸭子 3D 模型为 CC BY-SA-NC（非商业）。初始角色
  必须自研或外包（低多边形即可，物理与视觉解耦后美术自由度极大）
- 皮肤解锁：安卓走微信支付；iOS 走任务/分享解锁，规避虚拟支付限制

## 7. 错误处理

| 故障 | 处理 |
|---|---|
| 仿真容器崩溃 | 网关心跳检测 → 重建容器 → 鸭子回 home 位姿、位置从库恢复；客户端表现为"鸭子摔了一跤又站起来"（真实且可爱） |
| WebSocket 断线 | 客户端指数退避重连；期间意图停止（deadman）；重连后续传状态 |
| 冷启动慢/失败 | 孵化动画兜底 + 超时提示重试；网关限流防止重试风暴 |
| 支付丢单 | 支付回调幂等（订单号去重）；皮肤解锁事务化 |
| 服务器满载 | 排队页 + 预估等待时间（诚实优于假装能玩） |

## 8. 测试策略

- **仿真单元**：duck-sim 冒烟脚本化（已有全部命令：up/status/drive/skill）；
  网关回收逻辑单测
- **状态桥**：录制 `robot.state` 真实流做回放测试；30Hz 吞吐压测
- **小程序**：合成关节流驱动蒙皮动画的单元测试（无服务器可跑）；真机预览清单
- **E2E**：无头小程序模拟器跑"登录 → 冷启动 → 驾驶 30s → 技能 → 退出回收"
- **容量**：单 VM 压测至 50 并发会话，记录 P95 冷启动时间

## 9. 成功标准（MVP 验收）

| 维度 | 标准 |
|---|---|
| 体验 | 摇杆到动作端到端 < 300ms（P95）；冷启动 < 5s |
| 容量 | 单 VM 50 并发会话稳定 1 小时 |
| 产品 | 次日留存 ≥ 20%、七日 ≥ 8%（虚拟宠物品类参考线） |
| 链路 | 安卓内购完整走通（下单→支付→解锁→退款） |

## 10. 里程碑

| 阶段 | 内容 | 产出 |
|---|---|---|
| M1 | 仿真单元产品化：duck-sim 容器化模板 + 状态桥 + 最小网关 | 终端里能用 wscat 驾驶一只云鸭子 |
| M2 | 小程序壳：登录 + WebSocket + 虚拟摇杆 + 方块鸭子（占位模型）驱动 | 手机上能遛一只方块鸭 |
| M3 | 角色系统：正式初始角色 + 骨骼映射 + 声音 + 2–3 皮肤 + 内购 | 可上线的完整 MVP |
| M4 | 数据与留存：埋点 + 留存看板 + 容量压测 | 验证数据 |

## 11. 风险与开放问题

| 风险 | 应对 |
|---|---|
| 小程序 WebGL 性能分化（低端机） | threejs-miniprogram 早期真机测试；降级渲染（低面数/关阴影） |
| 微信对"游戏类"小程序的类目/资质要求 | 提前确认类目（虚拟宠物可能需游戏资质或走工具类） |
| 每会话容器成本 | v1 规模可接受；v2 路线已定（共享轻量仿真服务，客户端零改动） |
| 初始角色美术成本 | 低多边形 + 单一角色的皮骨分离让美术工作量可控 |
| RL 行为的"不可解释性"投诉（用户觉得卡住/异常） | 摔倒自起是特性；监控遥测 `robot.health` 类指标 |

## 12. v2 指针（不在本 spec 范围）

多人共享房间与合唱、麦克风 pet-detect、策略商店（接入 HF Hub 社区策略通道）、
轻量共享仿真服务（降本）、导流实体鸭。
